# Run 11 — experiment e3, captured on a GitHub-hosted runner

These are the raw artefacts behind run 11 in [`../../EVIDENCE.md`](../../EVIDENCE.md).
They are committed, rather than linked, because the links do not last: the CI
artifact expires on GitHub's retention window, and the run's logs follow it. An
evidence file whose proof lives behind a dead link proves nothing.

## What e3 is

The **no-fault control**. Two `cellrift` processes run about a second apart
against a freshly booted `gradiant/open5gs:2.8.0` HSS, over real SCTP, both
using the same `Origin-Host` (`test.cellrift.local`). **No fault is injected
anywhere** — no abort, no reset, no truncation.

The first process is answered. The second process's answer is built by the HSS
and then dropped:

```text
DROPPED 'Unable to forward answer to deleted / closed peer 'test.cellrift.local'.'
```

That is the whole point of this control. The failure had been recorded since
run 6 as "liveness after abort", and e3 shows the abort is irrelevant — a plain
reconnect under the same `Origin-Host` is sufficient. Companion controls (not
committed here, run locally) showed it is not SCTP-specific either: the same
drop occurs over TCP, and using a distinct `Origin-Host` for the second process
is answered every time.

## Reading the capture without being misled

Two traps, both real:

1. **The tail of the capture is Cellrift's own teardown**, not peer behaviour.
   After the second process's answer never arrives, its read times out and
   closes the association, so the trailing `SHUTDOWN` is self-inflicted.
2. **`req=False` rows are answers.** Correlate on `diameter.hopbyhopid`, not on
   ordering. In this run the first process's UAR and its UAA share
   `0xa2ab6b0f`; the second process's UAR (`0xcbc229d7`) has no matching row at
   all, which is the drop.

## Verifying it yourself

```sh
# The drop, in the peer's own words
grep "DROPPED" hss.log

# Two requests, one answer
awk -F, '$13==300 {print $1, $5"->"$6, "req="$14, "hbh="$15}' chunks.csv

# Real SCTP, not a TCP substitution
grep -c "used tcp" report.json report-2.json    # expect 0 for both

# Re-dissect from scratch
tshark -r e3.pcap -Y diameter
```
