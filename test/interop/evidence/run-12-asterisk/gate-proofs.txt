A gate that has never fired is untested. Each section below makes one refusal
fire, with the firing command, the verbatim output and the exit code. Two
kinds of noise are elided and replaced by a line count: the failure dump that
run-sip-scenario.sh prints after a refusal (run outputs and container log

## U1 up-sip.sh:131 wait_for_transports, fired by a bind conflict on 15060

A UDP socket holds 0.0.0.0:15060 before Asterisk boots. Observations the research left open, now answered: Asterisk still logs "Asterisk Ready." despite the failed bind, and the failed transport is NOT listed by "pjsip show transports" (only transport-tls is). So wait_for_transports is independently sufficient for a missing REQUIRED transport, and it is the gate that fires here, ahead of assert_no_bind_failure. The recorded exit is the exit of up-sip.sh itself.

```sh
python3 -c "import socket,time; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.bind((\"0.0.0.0\",15060)); time.sleep(90)" &
HOLDER=$!; sleep 1
bash test/interop/up-sip.sh; X=$?
echo "--- Ready / bind lines in the container log ---"
docker logs asterisk 2>&1 | grep -E "Asterisk Ready|Transport .* could not be started"
echo "--- pjsip show transports under the conflict ---"
docker exec asterisk asterisk -rx "pjsip show transports"
kill $HOLDER; exit $X
```

## U2 up-sip.sh:108 assert_no_bind_failure, fired by a bind conflict on a third transport

Because a failed transport drops out of the transport list (U1), assert_no_bind_failure cannot be reached by colliding on 15060 or 15061: wait_for_transports refuses first. It is reached when a transport OTHER than the two required ones fails: both required addresses are listed, wait_for_transports passes, and only the log shows the failure. The probe config adds [transport-extra] on 15062, which a UDP socket holds. The probe config is a scratch file inside the repo, deleted afterwards.

```sh
python3 -c "import socket,time; s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.bind((\"0.0.0.0\",15062)); time.sleep(60)" &
HOLDER=$!; sleep 1
PJSIP_CONF=test/interop/asterisk/.probe-pjsip.conf bash test/interop/up-sip.sh; X=$?
echo "--- pjsip show transports (both required addresses ARE listed) ---"
docker exec asterisk asterisk -rx "pjsip show transports"
echo "--- Ready line ---"
docker logs asterisk 2>&1 | grep "Asterisk Ready"
kill $HOLDER; exit $X
```

## U3 up-sip.sh:131 wait_for_transports, fired by a TLS transport that cannot start (missing certificate file)

cert_file points at a path that does not exist in the container. PJSIP_CONF is mounted as $PWD/$PJSIP_CONF, so the probe config is a scratch file inside the repo (test/interop/asterisk/.probe-pjsip.conf), deleted afterwards. The container log carries Asterisk own complaint about the certificate. Here the READY check, not the bind check, refuses, which agrees with U1: a transport that failed to start is absent from the list.

## A8 run-sip-scenario.sh:165 derive_verified_tls_scenario, missing ca_file in the derived file (FIRED via a CA path containing "&")

The expectation going in was that this refusal could not be reached: line 159
fixes the substitution count at exactly one, and line 160 is the sed that
writes "ca_file: $CA_CRT" on that line, so the text should always be present.

`\1ca_file: $CA_CRT` with `|` as the delimiter, and in a sed replacement `&`

defence in depth, and it is fired below. The derived file after the refusal is
